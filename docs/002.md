# Next Static Studio — UX & 기능 명세 v1

> **포지셔닝**: Next.js 의미론을 코딩 중에 "탐정"처럼 보여주는 정적 IDE
> **시각 톤**: white / light / hairline (1px line) / 정보 밀도는 높지만 시각 잡음은 낮음
> **인터랙션 톤**: 판정하지 않는다. **Evidence + Confidence + ?**로 보여주고 개발자가 판단한다.

---

## 0. 디자인 철학 (이 문서 전체 관통)

### 0.1 5대 원칙

```
1. Detective, not Judge      — 판정 대신 증거 + 신뢰도
2. Density without Noise     — 정보는 많이, 시각 잡음은 최소
3. Evidence is First Class   — 모든 경고는 trace를 펼칠 수 있다
4. Reversible Default        — 위험한 액션은 preview → confirm
5. Hairline > Shadow         — 1px 선으로 구획. 그림자/그라데이션 지양
```

### 0.2 정적 분석 결과의 4단계 표현

```
Confidence  | 시각 표현                | 인터랙션 톤
----------- | ----------------------- | -------------------
High (●)    | solid underline / chip  | 명령형: "Fix" / "Block"
Medium (◐)  | dashed underline / chip | 권유형: "Review" / "Suggest"
Low (○)     | dotted underline + [?]  | 질문형: "Possibly?" / "Show why"
Info        | subtle dot in gutter    | 중립형: hover로만 노출
```

핵심: **Low confidence 경고는 절대 squiggle wave를 사용하지 않는다.** 점선(dotted)에 `[?]` 배지로만 표시. squiggle은 Medium/High 전용.

## 3. 에디터 표면 (Editor Surfaces)

### 3.1 Gutter (라인 넘버 영역)

5개 컬럼으로 분할:

```
│  [A] │ [B] │ [C] │   [D]   │ [E] │
   3    ●     S       42       ▶
```

| 컬럼 | 폭 | 내용 |
|-----|----|------|
| A | 28px | 라인 번호 |
| B | 8px  | severity dot (err/warn/hint) — 줄 안의 가장 강한 1개 |
| C | 8px  | classification mark (S/D/I/C — static/dynamic/isr/client) |
| D | 24px | blast number — 이 줄이 만지는 라우트/파일 수 (`↓42`, `↑12`) |
| E | 12px | breakpoint / fold 등 기존 IDE 기능 |

**hover에서만 D 컬럼 숫자가 굵어지고 옆에 `↗ open map` 미니 버튼**이 나옴 → 클릭하면 Blast Radius Map 오버레이.

### 3.2 Inline CodeLens (라인 위)

함수/파일/심볼 위에 한 줄 lens. **회색 톤, 13px**. 텍스트로 끝내고 색은 confidence chip에만 사용.

```
함수 위:
⌃ FUNCTION  updateProduct()  · Server Action  · ▲ 3 risks
                              ↑ chip            ↑ severity
파일 최상단 (route file):
⌃ ROUTE  /products/[id]  ●ISR  · ↓ 4 risks · cost B  · client 12KB
                          ↑ confidence
fetch / 'use client' 위에:
⌃ FETCH  /api/products  · default cache  · ⚠ stale risk?
⌃ CLIENT BOUNDARY  · ↑ 38 files  · ~260KB
```

클릭 동작:
- chip 클릭 → 우측 Inspector 해당 섹션으로 점프
- `↓ 4 risks` 클릭 → Problems 패널 필터링 (이 lens 범위만)
- `↑ 38 files` 클릭 → Blast Radius Map 오버레이

### 3.3 Inline Annotation (라인 끝 ghost text)

라인 우측 빈 공간에 회색 `text-3` ghost text. 의미를 짧게 표시. **편집 시 자동 hide**.

```
const c = await cookies()              → dynamic (this route)
fetch("/api/products")                 → tag: products  · revalidate 60
notFound()                             → throws NEXT_NOT_FOUND
"use client"                           → ↑ 38 files in client tree
import { db } from "@/lib/db"          → server-only · used by 12 routes
```

설정으로 **밀도**를 조절 (off / 핵심만 / 풍부).

### 3.4 Squiggle / Underline 규약

```
─ red wave        High Error              (예: secret leak to client)
─ amber wave      High/Medium Warning     (예: try/catch around redirect())
─ amber dashed    Medium Warning          (예: missing revalidate)
─ gray dotted     Low/Hint                (예: possibly dynamic?)
─ blue dotted     Info / migration hint   (예: Next 15 async API)
```

**Low confidence는 wave 절대 금지.** dotted line + `[?]` chip만.

### 3.5 Selection Action Bar (플로팅)

코드 선택 시 위쪽에 떠오르는 바. 선택 컨텍스트에 따라 액션 바뀜. **white bg, 1px border, 약한 shadow-pop**.

```
선택이 컴포넌트 함수일 때:
┌────────────────────────────────────────────────────────────────┐
│ Convert ▾  │ Extract ▾  │ Add Cache  │ Wrap Auth  │ ⋯          │
└────────────────────────────────────────────────────────────────┘

선택이 fetch 호출일 때:
┌────────────────────────────────────────────────────────────────┐
│ + cache policy ▾  │ + tag  │ Wrap helper  │ ⋯                  │
└────────────────────────────────────────────────────────────────┘

선택이 'use client' 라인일 때:
┌────────────────────────────────────────────────────────────────┐
│ Show blast  │ Move down  │ Extract island  │ Convert to server │
└────────────────────────────────────────────────────────────────┘
```

`▾`는 옵션 펼침. 액션 실행 전 항상 **patch preview**가 옆에 펼쳐진다 (3.5.a).

### 3.6 Hover Popover (Evidence Card)

모든 진단 hover는 동일한 anatomy.

```
┌─────────────────────────────────────────────────┐
│ ◐ Possibly Dynamic                  [?]         │  ← title + confidence
│   /products/[id]  ·  why-dynamic                │  ← scope · rule id
├─────────────────────────────────────────────────┤
│ Evidence                                        │
│   1. cookies() in app/layout.tsx:8        →    │
│   2. fetch(no-store) in page.tsx:14       →    │
│   3. searchParams accessed page.tsx:22    →    │
├─────────────────────────────────────────────────┤
│ Impact                                          │
│   • affects 12 routes                           │
│   • CDN cache lost                              │
│   • cost B → D                                  │
├─────────────────────────────────────────────────┤
│ Confidence  Medium                              │
│ Reason      indirect helper call (getSession)   │
├─────────────────────────────────────────────────┤
│ [ Show trace ]  [ Quick fix ▾ ]  [ Mute ▾ ]    │
└─────────────────────────────────────────────────┘
```

- `→` 클릭 → 해당 라인으로 점프 (peek은 3.7 참조)
- `Show trace` → Evidence Tracer 오버레이 (4.1)
- `Quick fix ▾` → 후보 패치 리스트
- `Mute ▾` → 옵션: line / file / route / project / rule

### 3.7 Decoration (배경 강조)

```
배경 강조는 매우 절제되게:
- dynamic-trigger 라인: 좌측 사인 컬럼에 1px 노란색 vertical line + 라인 우측 끝 미세 하이라이트
- secret leak: 빨간 vertical line (좌측 사인 컬럼)
- client island 시작: 분홍 vertical line + 위쪽 1px hairline 시작 표시
- 'use server' 함수 영역: 하늘 톤 vertical line
```

라인 자체에 배경을 깔지 않는다 (가독성). **vertical accent line은 8~12px 폭의 보조 컬럼**에서만.

### 3.8 Confidence 배지 (라인 위 inline)

```
                  ●ERR    HIGH error
                  ◐WARN   medium warning
                  ○?      low / question
                  ▎HINT   hint (gray)
```

배지는 inline annotation과 같은 위치에 들어가지만, **항상 가장 우선순위 높은 1개만**. 동일 라인 다중 진단은 hover에서 펼침.

### 3.9 Breadcrumb (semantic)

에디터 위쪽 breadcrumb. 일반 IDE의 파일 경로 + symbol에 **Next 의미를 결합**.

```
app › (shop) › products › [id] › page.tsx › Page() · Server
└─ route group (URL 영향 X)        └─ dynamic param      └─ component role
```

- 각 segment 클릭 → 좌측 Routes 트리 해당 노드로 이동.
- 마지막 component segment 옆에 role badge (`Server` / `Client` / `Action`).

## 4. 오버레이 & 플로팅 UI

### 4.1 Evidence Tracer (오버레이 모드)

`Show trace` 버튼 / `⌘⇧E` 키.

화면 가운데에 **반투명 layer** + 가운데 사각 패널 + 좌측 호출 트리.

```
┌──────────────── Evidence Tracer · Why dynamic? ─────────────────┐
│                                                                 │
│  /products/[id]                                                 │
│                                                                 │
│  app/(shop)/products/[id]/page.tsx                              │
│   └─ getSession()           page.tsx:14   ↗                    │
│       └─ cookies()          lib/auth.ts:6 ↗  ← root cause      │
│                                                                 │
│  Affected routes (12)                              [show all]   │
│   /products/[id]                                                │
│   /products                                                     │
│   /home                                                         │
│   ...                                                           │
│                                                                 │
│ [ Suggest move into client island ]   [ Close (Esc) ]           │
└─────────────────────────────────────────────────────────────────┘
```

- 트리의 각 노드 hover → 미니 코드 peek (해당 5줄).
- 노드 클릭 → 에디터로 점프하면서 오버레이는 그대로 (re-pin 가능).
- 우측 패널의 Inspector도 자동으로 해당 evidence에 동기화.

### 4.2 Blast Radius Map (오버레이)

`gutter D 컬럼 클릭` / `⌘⇧B`.

```
│  AppShell.tsx ●                                                 │
│   ├── Header.tsx        12 imports                              │
```

## 6. LSP 강화

기존 LSP에 **Next 의미를 인지한 layer**를 얹는다. 모든 강화는 **기존 단축키와 동일하게 동작**하지만 결과가 풍부해진다.

### 6.1 Go to Definition (semantic-aware)

| 커서 위치 | 동작 |
|-----------|------|
| 라우트 path 문자열 (`"/products/[id]"`) | `app/products/[id]/page.tsx`로 점프 |
| `<Link href="/x">`의 href | 해당 page.tsx |
| `redirect("/x")` / `router.push("/x")` | 해당 page.tsx |
| cache tag 문자열 (`"products"`) | tag 정의 origin (가장 먼저 사용된 fetch site) + lineage 미니뷰 |
| `revalidateTag("products")` | tag 사용 fetch 사이트들 (peek list) |
| Server Action 식별자 | 정의 위치 (form `action={fn}`에서도 동작) |
| `params.id` / `searchParams.x` | Params/Search Schema (자동 생성된 타입) 정의 |
| import된 `db`, `crypto` 등 | 서버 전용 마킹 + 사용처 |

## 12. 기능별 UX 카탈로그 (클러스터링)

각 기능을 동일한 6필드로 명세:

```
WHERE   어떤 표면(gutter/inline/hover/panel/overlay)에 나오나
TRIGGER 어떻게 발견되고 어떻게 펼쳐지나
VISUAL  시각 요소 (뱃지/색/아이콘)
ACTION  사용자 인터랙션 (click/right-click/hotkey/quick-fix)
PANEL   우측/하단 패널의 상세 뷰
NOTE    confidence 정책, false positive 처리
```

> 진단(diagnostic) 표현은 모두 §3 (에디터 표면) + §4 (오버레이) + §8 (Inspector)에 의존한다. 아래는 그 위에 얹는 **기능별 차이점만** 기술한다.

### 12.A 클러스터: Rendering & Why-Dynamic

#### A1. Why Dynamic Lens
- **WHERE** 라우트 파일 page.tsx 최상단 inline lens, 그리고 dynamic-trigger 라인의 inline annotation
- **TRIGGER** dynamic API (cookies/headers/draftMode/searchParams) 직간접 사용 감지
- **VISUAL** 라인 lens: `⌃ ROUTE /x ◐DYN ?  cause: cookies()@layout.tsx:8 · ↓12 routes`. dynamic-trigger 라인은 좌측 사인 컬럼에 노란 vertical line.
- **ACTION** lens 클릭 → Evidence Tracer 오버레이. 라인 hover → Evidence Card. 우클릭 → "Move into client island" / "Wrap in helper".
- **PANEL** Route Contract Inspector → Rendering 섹션에 cause + propagation 트리.
- **NOTE** indirect helper 호출은 항상 Confidence Medium 이하. 직접 `cookies()` 호출만 High.

#### A2. Static Rendering Feasibility
- **WHERE** 라우트 트리 행에 분류 칩 (`●ISR`, `◐DYN ?`)
- **TRIGGER** 항상 백그라운드. 변경 시 우측 Inspector의 Rendering 섹션 갱신.
- **VISUAL** 칩 색: 정적 녹색, ISR 청색, dynamic 황색. confidence dot 좌측에.
- **ACTION** 칩 클릭 → Why Dynamic Lens 펼침.
- **PANEL** Project Health에 분류 분포.
- **NOTE** 단계별 confidence 표기 필수 (없으면 절대 분류 칩 보여주지 않음 — `?` 표시).

#### A3. Cost Class & Regression
- **WHERE** Status Bar `cost X`, Inspector "Project Health", Semantic Diff 행
- **VISUAL** 클래스 글자: A(녹색)·B·C·D(주황)·E(빨강)
- **ACTION** Status Bar 칸 클릭 → 분포 미니 차트 + hotspot 리스트
- **NOTE** PR diff에서 클래스 회귀가 있으면 Semantic Diff 패널 상단에 배너.

#### A4. PPR Static Shell Compiler
- **WHERE** 페이지 파일에서 `<Suspense>` 라인 lens, gutter 사인 컬럼의 보라 vertical line으로 dynamic hole 영역 표시
- **TRIGGER** `experimental_ppr` 또는 Next 16 cacheComponents 활성화
- **VISUAL** gutter 옆 세로 막대로 "static shell" / "dynamic hole" 영역 구분 (이중 컬러 바). 라인 lens: `⌃ DYNAMIC HOLE  cookies() · fallback: ProductSkeleton`.
- **ACTION** 라인 lens 클릭 → "PPR Map" 오버레이 (route 전체에서 정적 shell vs dynamic hole 시각화)
- **PANEL** Inspector → Rendering 섹션에 PPR map 미니뷰.
- **NOTE** PPR 켜졌을 때만 동작.

#### A5. Async Request API Migration
- **WHERE** 동기 사용 라인의 squiggle (blue dotted, info severity) + inline annotation `→ async in Next 15`
- **TRIGGER** Next 15+ 프로젝트에서 `cookies()` 등을 `await` 없이 사용
- **VISUAL** blue dotted line + chip `[mig 15]`
- **ACTION** Quick fix `Migrate to async`. Command palette: "Migrate Next 14→15 (preview)" → diff 큰 화면에서 일괄 검토.
- **PANEL** Migration Inspector.
- **NOTE** Confidence 항상 High (구문 단위 검사). 라이브러리/노드모듈 파일은 제외.

#### A6. `'use cache'` Analyzer
- **WHERE** 'use cache' 디렉티브가 있는 함수 위 lens. 위반 라인 squiggle.
- **VISUAL** 함수 lens: `⌃ CACHED FN  · life: hours · tags: products, product:{id}`. 위반 (closure 캡처, 비직렬화 인자) 라인은 amber dashed.
- **ACTION** Quick fix: `Lift closure to argument` / `Add cacheTag()` / `Add cacheLife()`.
- **PANEL** Inspector → "Cached Function" 섹션에 cacheLife/cacheTag 매트릭스 + 영향 라우트.
- **NOTE** Next 15+ only. Confidence는 closure 검사는 High, 외부 dep 추적은 Medium.

### 12.J 클러스터: Hydration / Render-time

#### J1. Hydration Mismatch Predictor
- **WHERE** `Date.now()` / `Math.random()` / `Intl.*` / `typeof window` 라인 squiggle (amber dotted)
- **VISUAL** chip `[?hydration]` (Low/Medium confidence)
- **ACTION** Quick fix: 패턴별 가이드 (`useEffect`로 이동 / `suppressHydrationWarning` 정당화).

#### J2. Theme/Locale FOUC
- **WHERE** root layout에서 cookie 기반 theme 설정 라인 lens
- **VISUAL** chip `[?fouc]` + `next-themes 사용 시 className inline 권장`
- **ACTION** Quick fix: `Use next-themes script pattern`.

### 12.K 클러스터: Migration / Version

#### K1. Next 14 → 15 Async APIs (A5와 동일 — 통합 보기)
#### K2. `unstable_cache` → `'use cache'`
#### K3. `serverComponentsExternalPackages` → `serverExternalPackages`

각각 Migration Inspector에서 일괄 미리보기 + Apply.

### 12.L 클러스터: Diff / Review

#### L1. Diff-aware Behavior Change
- **WHERE** Semantic Diff 패널 (§9.2). 그리고 에디터에서 변경된 라인 옆 ghost annotation `→ behavior change: ISR → Dynamic`.
- **ACTION** ghost annotation 클릭 → Semantic Diff 패널 해당 행으로 점프.

#### L2. PR Comment Generator
- **WHERE** Semantic Diff 상단 버튼
- **VISUAL** 생성된 코멘트 미리보기 + edit
- **ACTION** clipboard 복사 / GitHub 어댑터로 직접 첨부 (옵션).

#### L3. Pre-commit Gate
- **WHERE** 커밋 시 모달 (사용자가 활성화한 경우)
- **VISUAL** blocking / warnings 분리. block 항목은 `[Open] [Mute (with reason)]`.
- **ACTION** "Mute with reason"은 reason 텍스트 필수 → 커밋 메시지에 자동 첨부.

#### L4. AI Patch Admission Gate
- **WHERE** AI 에이전트가 만든 변경(IDE에서 인식 가능한 source)에 대해 자동 Semantic Diff 검사 → 통과 못하면 커밋 차단 / 사람 리뷰 필수 표시.
- **VISUAL** Semantic Diff 패널 상단에 `[ AI patch · 3 reasons to reject ]` 배너.

## 14. 인터랙션 플로우 예시

### 14.1 "왜 이 라우트가 dynamic이야?"

```
1. /products/[id]/page.tsx 열림
2. 상단 lens: ⌃ ROUTE /products/[id]  ◐DYN ?  cause: cookies()@layout.tsx:8
3. lens "cause: cookies()" 클릭 → Evidence Tracer 오버레이
4. 트리에서 lib/auth.ts:6 → cookies() 노드 클릭 → 에디터 점프
5. cookies() 라인의 inline lens에 "Suggest move into client island" 버튼
6. 클릭 → Patch Preview → Apply
7. Status Bar의 분류가 ◐DYN → ●ISR로 즉시 갱신
8. Semantic Diff 패널에 "/products: dynamic → ISR" 행이 추가
```

### 14.2 "이 fetch에 캐시 정책 빠진 거 같은데?"

```
1. 라인 끝 ghost annotation: "→ default cache · ⚠ stale risk?"
2. ⌥⏎ → Quick Fix: ◇ Add cache: revalidate 60  ◇ Add tag products  ...
3. "Add tag products" hover → Patch Preview에 behavior diff
4. Apply → fetch에 next.tags 추가, ghost annotation도 "→ tag: products" 변경
5. Cache Lineage 패널 자동 갱신 → "products" 태그 producers +1
6. mutation 함수 (updateProduct)에 lens가 ⚠ → ✓로 바뀌고 pair 매트릭스 ✓
```

### 14.3 "AppShell에 'use client' 박혀있는데 영향이 얼마나 돼?"

```
1. AppShell.tsx 1번 라인의 "use client" lens: ⌃ CLIENT BOUNDARY · ↑38 files · ~260KB · ↗ map
2. ↗ map 클릭 → Blast Radius Map
3. Suggested optimal boundaries: SearchBox, UserMenu, ThemeToggle (3)
4. "Preview refactor" 클릭 → 3개 island 추출 + AppShell.tsx에서 'use client' 제거되는 diff
5. behavior diff: rendering 동일, client KB 260 → 46, +29 routes 정적 회복
6. Apply → 새 파일 3개 생성, import 자동 수정
7. 좌측 Islands 탭 갱신, Status Bar 비용 클래스 D → B
```

### 14.4 "PR 올리기 전에 의미 변화 확인"

```
1. ⌘⇧D → Semantic Diff 패널
2. "/products: ISR → Dynamic" 행 hover → cause: cookies()@layout.tsx 추가됨
3. 행 우클릭 → "Generate PR comment"
4. 코멘트 미리보기:
     "This change converts /products family from ISR to Dynamic.
      Cause: cookies() added in app/(shop)/layout.tsx:8.
      Impact: 12 routes lose CDN cache benefit."
5. Copy → PR에 붙여넣기
6. (옵션) 커밋 시 Pre-commit Gate가 같은 정보를 한 번 더 표시 + Mute with reason 강제
```

## 15. 디자인 토큰 / 컴포넌트 부록

### 15.1 핵심 컴포넌트

| 이름 | 용도 | 시각 |
|------|------|------|
| `Chip` | confidence/severity 칩 | 1px border, 6/10 padding, 11px caps text |
| `EvidenceCard` | hover popover, problem expansion 동일 anatomy | white bg, 1px border, shadow-pop |
| `LensLine` | inline codelens | 13px text-2, chip 지원 |
| `GhostAnnotation` | 라인 끝 회색 텍스트 | 11px text-3, italic 옵션 |
| `SignBar` | gutter 사인 컬럼 vertical line | 2px / 4px 폭 가능, severity 색 |
| `PatchPreview` | 패치 미리보기 카드 | diff + behavior diff 분리 |
| `OverlayPanel` | What-if / Tracer / Blast Map | 가운데 모달, 반투명 backdrop |
| `Inspector` | 우측 패널의 sectioned panel | collapse/pin |
| `RouteRow` | 라우트 트리 행 | icon + label + chips + actions |
| `ConfidenceDot` | ● ◐ ○ | 8px 원, severity와 무관한 색 (회색 톤) |

### 15.2 인터랙션 규약

```
- 모든 진단은 hover 200ms 후 popover.
- Apply가 있는 액션은 최소 1번의 preview 단계를 거친다 (예외: rename — 단, 미리보기 카드 펼침).
- Mute는 항상 4단계 스코프 선택 (line/file/route/project).
- Mute는 reason 입력을 강제 (project/rule scope에서만 — line/file은 선택).
- 모든 quick fix는 "Apply to all similar" 옵션을 가진다 (가능한 경우).
```

### 15.3 접근성

```
- 모든 색상에 의존하지 않는 표식 (chip 텍스트, dot 모양 ●/◐/○ 차이).
- 키보드 only 작동 보장: lens, popover, overlay 전부 포커스 트랩 지원.
- 진단 popover는 aria-live="polite". Evidence Tracer는 dialog role.
- 점선/굵기 차이를 색에 의존하지 않게 (e.g. amber dashed vs gray dotted는 패턴이 달라야).
- 모션은 항상 prefers-reduced-motion 존중.
```

### 15.4 성능 / 정보 밀도 가이드

```
- 한 라인에 lens + ghost annotation + signbar + chip이 모두 노출되면 잡음.
  → 우선순위:  red squiggle > lens(High) > chip(High) > ghost > 분류 칩 > confidence dot.
  같은 라인에 동일 정보면 묶음.
- inline lens는 라우트 파일/액션/주요 함수 위에만 default ON. 일반 함수는 off.
- 사용자는 "Density" 설정으로 3단계 (Minimal / Default / Rich) 전환 가능.
- 좌측 패널 트리는 가상 스크롤. 큰 모노레포에서도 부드럽게.
```

### 15.5 화면 잡음 방지 규칙

```
1. 한 파일에 같은 카테고리 진단 5개 이상이면, "5+ similar" 칩으로 묶음.
   클릭 시 펼쳐서 개별 노출.
2. Confidence Low 진단은 dotted line만, chip은 hover에서만.
3. 같은 routine cause(예: 같은 cookies() 한 줄이 12개 라우트에 영향)는
   원인 라인 1곳에만 진단 표시 + "12 affected" 링크. 나머지 라인엔 inlay hint만.
4. 한 라인의 동일 origin 다중 진단은 popover 안에서 stack.
5. ghost annotation은 라인 폭에 따라 자동 truncate. hover에서 풀.
```

```
Color Mode
  - Light (default)
  - Light High Contrast
  - (Dark는 v2)

Per-rule
  - severity, confidence 임계값
  - autofix 자동 적용 여부 (off / suggest / on save)
```
